Surface ask vs. real problem

The surface ask

"Give employees a chatbot for IT/HR questions so the helpdesk queue shrinks."

The real problem

The queue is expensive because answering requires acting — resetting access, filing tickets, provisioning — and every action carries blast radius, tenant/clearance boundaries, and an audit obligation. A read-only bot deflects the easy half and leaves the costly half untouched.

Where AI fits — and where it must not

Success criteria (what "it works" means)

  • Safe to leave running: every safety property is a tested invariant; the deploy blocks if one regresses.
  • Deflection with action: resolves the acting half under human approval, not just the answering half.
  • Provable: every run is traced with its node path, tokens, and control status; approvals are auditable.
  • Portable: a new domain is four slots (golden set → corpus → tools → output contract); governance unchanged.

Build-first (impact ÷ effort)

FIRST the control plane — authz, tenant isolation, approval binding, injection-inert retrieval. THEN quality — retrieval recall, groundedness, model selection.

Rationale: the differentiator isn't answering (everyone ships that) — it's being bounded and continuously proven. See the problem breakdown and multilayer audit for the computed version of this ranking.
