# workflows/

Declarative maps of this agent's flows to the workflow patterns and the controls each step carries. The
method lives in **[PATTERNS.md](PATTERNS.md)** (workflow-vs-agent, the 5 canonical patterns, the
determination method) — it is domain-agnostic and carried verbatim into every engagement.

Each `*.yaml` here is one real flow. Nothing is invented (J-01):
- every `node` is a real graph node in `agent/graph.py`,
- every tool is in `agent/tool_registry.json`,
- every control is a `D-###` row in `MANIFEST.md`,
- `pattern` is one of the 5 canonical patterns (or `dynamic-agent`, the agent axis of PATTERNS.md §1).

`tests/test_workflows.py` is the catch-proof: it fails if any flow names a tool not in the registry, a
control not in the MANIFEST, or an unknown pattern label.

## What ships in the skeleton (FRAME flows)
These describe the frame's own graph, using the frame's generic tools (`search_kb` read, `submit_action`
action). They hold in **every** domain — a domain reuses the shape with its own tools, unchanged controls.

| File | Pattern | Business request | Human gate |
|---|---|---|---|
| [read-answer.yaml](read-answer.yaml) | prompt-chaining | answer from the retrieved, scoped corpus | none (no side effect) |
| [gated-action.yaml](gated-action.yaml) | evaluator-optimizer *(gate)* | a side-effecting request — propose→approve | `approval` node |
| [a2a.yaml](a2a.yaml) | prompt-chaining *(across a boundary)* | another agent calls in; the gate still fires | callee `approval`, via the caller's channel |
| [dynamic-react-core.yaml](dynamic-react-core.yaml) | dynamic-agent | the general unknown-path case the others wrap | inherited (routes to `approval`) |

## Declaring your domain's flows
1. Copy **[templates/domain-flow.template.yaml](templates/domain-flow.template.yaml)** to
   `workflows/<your-flow>.yaml`.
2. Fill every `SLOT`: pattern (PATTERNS.md §3), ordered steps (real graph nodes), tools (from the
   registry), controls (D-rows whose worst case each step satisfies), and the human-gate point.
3. `python -m presentation.build_workflows` (or `make showcase`) renders it behind `/workflows`, led by
   the determination method. `make check` runs `tests/test_workflows.py` to keep it honest.

Files under `templates/` are not rendered or validated — only real declarations in `workflows/*.yaml` are.

## Tools → flows (frame flows)
Source: `agent/tool_registry.json` (read = `side_effect:false`, action = `side_effect:true`).

| Tool | Kind | Used by |
|---|---|---|
| `search_kb` | read | read-answer · gated-action · a2a · dynamic-react-core |
| `submit_action` | action | gated-action · a2a · dynamic-react-core (never read-answer; always via `approval`) |

## Rendered
`GET /workflows` (showcase stop 13) renders these — leading with the determination method, then each
flow's step/tool/control sequence and its human-gate point. Generated by
`presentation/build_workflows.py`; empty → an honest "pending — declare workflows/" card.
